# Payroll Module — လစာတွက်ချက်ခြင်း

> Customer Presentation အတွက် Module တစ်ခုချင်းစီ ရှင်းလင်းချက်။ အနှစ်ချုပ်ကို [CLIENT-MODULE-GUIDE.md](../CLIENT-MODULE-GUIDE.md) တွင် ကြည့်ပါ။

> **အရေးကြီး:** လက်ရှိ Payroll တွက်ချက်မှုသည် **Demo စည်းမျဉ်း** ဖြစ်သည်။ **အခွန် (Income Tax)၊ လူမှုဖူလုံရေး (SSB) မပါဝင်ပါ**၊ ဘဏ်သို့ ငွေပေးချေမှု မပြုလုပ်ပါ။ "Mark as Paid" သည် Status မှတ်သားရုံသာ ဖြစ်သည်။

## 1. ဘာကြောင့် လိုအပ်သလဲ

လစာတွက်ရာတွင် HR က ခွင့်၊ OT၊ ဝင်/ထွက်ရက်များကို Excel တွင် လက်ဖြင့် ပေါင်းနုတ်ရသဖြင့် အချိန်ကုန်၍ အမှားများသည်။ Payroll Module က အဲဒီ ဒေတာများကို **အလိုအလျောက် ချိတ်ပြီး** တွက်ပေးသည်။

## 2. အလုပ်လုပ်ပုံ (Flow)

```
① Salary Components ဖန်တီး  (Allowance / Deduction အမျိုးအစားများ)
        ↓
② Salary Structures ဖန်တီး  (Component များကို အစုအဝေးပြုလုပ်)
        ↓
③ Employee Salaries သတ်မှတ်  (ဝန်ထမ်းတစ်ဦးစီ၏ Basic + Structure)
        ↓
④ Payroll Processing        (လအလိုက် Period ဖွင့် → Process → Approve → Mark as Paid)
        ↓
⑤ Payslips / History        (စလစ်ကြည့်/ပရင့်၊ လအလိုက် နှိုင်းယှဉ်)
```

① မှ ③ အထိကို တစ်ကြိမ် Setup လုပ်ပြီးလျှင် လစဉ် ④ ကိုသာ လုပ်ရသည်။

## 3. Screen တစ်ခုချင်းစီ

| Screen | ရည်ရွယ်ချက် |
|---|---|
| **Salary Components** | ဝင်ငွေ (Earning) / နုတ်ငွေ (Deduction) အမျိုးအစား။ တန်ဖိုးသတ်မှတ်ပုံ ၃ မျိုး — **ပုံသေပမာဏ**၊ **Basic ၏ %**၊ **Gross ၏ %** |
| **Salary Structures** | Component များကို အစုအဝေးပြုလုပ်ထားသော Template (ဥပမာ "Officer Package") |
| **Employee Salaries** | ဝန်ထမ်းတစ်ဦးစီ၏ Basic လစာ + Structure၊ **Effective Date** ဖြင့်။ လစာတိုးလျှင် အသစ်တစ်ကြောင်း ထပ်ထည့် (မှတ်တမ်းဟောင်း ကျန်ရစ်) |
| **Payroll Processing** | လစဉ် Period (ခုနှစ် + လ) ဖန်တီးပြီး Process → Approve → Paid အဆင့်ဆင့် လုပ်ရန် |
| **Payroll Review** | Period တစ်ခုအတွင်း ဝန်ထမ်းအလိုက် Gross / Deduction / Net စစ်ဆေးရန် |
| **Payslips** | Period အလိုက် Payslip စာရင်း၊ တစ်ဦးချင်းကြည့်၊ ပရင့်ထုတ် |
| **Payroll History** | လအလိုက် Gross နှင့် Net နှိုင်းယှဉ် (Chart နှင့် Table) |

## 4. တွက်ချက်ပုံ

| အချက် | စည်းမျဉ်း |
|---|---|
| အလုပ်ဝင်/ထွက်လ | **ပြက္ခဒိန်ရက်အလိုက် အချိုးကျ (Proration)** |
| Allowance | Component အတိုင်း ပေါင်း |
| Overtime | နာရီစား နှုန်း × **၁.၅ ဆ** (နာရီစားနှုန်း = Basic ÷ (အလုပ်ရက် × ၈ နာရီ)) |
| လစာမဲ့ခွင့် | နေ့ပျမ်းမျှလစာ ဖြင့် နုတ် |
| Deduction | Basic သို့မဟုတ် Gross အပေါ် % ဖြင့် သို့မဟုတ် ပုံသေ |
| **Net လစာ** | **Gross − Deductions** |

ဥပမာ (ရှင်းပြရန်သာ): Basic 600,000 + Allowance 50,000 + OT 20,000 = Gross 670,000 → Deduction 30,000 → Net 640,000။

## 5. ထိန်းချုပ်မှု နှင့် ကာကွယ်မှု

- **Period အပိုင်း:** လတစ်လလျှင် Period တစ်ခုသာ။ အနာဂတ်လကို မဖန်တီးနိုင်။
- **အဆင့်ဆင့်:** Process → Approve → Mark as Paid။ **အရင်လ မပြီးမချင်း နောက်လကို မလုပ်နိုင်။**
- **ပြန်ပြင်နိုင်ခြင်း:** Process/Approve ပြီး Period ကို **Draft သို့ ပြန်လှည့်** နိုင်သည် (Payslip များ ဖျက်ပြီး ပြန်တွက်)။ **Paid ပြီးလျှင် အပြီးအပိုင်** ဖြစ်သည်။
- **လစာမသတ်မှတ်ထားသော ဝန်ထမ်း:** ကျော်ထားပြီး သတိပေးချက်ပြသည်။
- **လစာအကန့်အသတ်:** Basic သည် ဝန်ထမ်း၏ Job Grade ၏ Salary Band အတွင်း ရှိရမည်။
- **Payslip သည် Snapshot:** ထုတ်ပြီးနောက် Setup ပြောင်းလဲမှုများက ဟောင်း Payslip ကို မထိခိုက်။ Audit အတွက် ယုံကြည်စိတ်ချရသည်။

## 6. အခြား Module များနှင့် ချိတ်ဆက်မှု

| ဒေတာ | ဘယ်ကရသလဲ |
|---|---|
| ဝန်ထမ်း၊ ဝင်/ထွက်ရက် | Employees |
| လစာအကွာအဝေး | Organization → Job Grades |
| OT နာရီ | Attendance → **ခွင့်ပြုပြီး** OT တောင်းခံမှုများ (နေ့စဉ်တက်ရောက်မှုမှတ်တမ်းကို မဖတ်ပါ) |
| လစာမဲ့ခွင့် | Leave |
| အားလပ်ရက် (အလုပ်ရက်ရေတွက်ရန်) | Holiday Calendar |

## 7. Customer ထံ ပြောနိုင်သော အကျိုးကျေးဇူး

1. လစာတွက်ချိန် ရက်များမှ မိနစ်ပိုင်းသို့ လျော့ကျစေသည်။
2. တွက်ချက်ပုံ ပွင့်လင်းမြင်သာ — Payslip တွင် Component တစ်ခုချင်း ပေါ်သည်။
3. အဆင့်ဆင့် Approval ဖြင့် အမှားနှင့် လိမ်လည်မှု လျော့ကျစေသည်။
4. လအလိုက် Gross / Net History ဖြင့် လစာကုန်ကျစရိတ် Trend ကို မြင်နိုင်သည်။

## 8. Demo ပြသရန် အဆင့်များ (၃–၄ မိနစ်)

1. **Salary Components** နှင့် **Salary Structures** ကို အကျဉ်းပြ။
2. **Employee Salaries** တွင် Basic ကို Job Grade အကွာအဝေးပြင်ပ ထည့်ကြည့်ပြီး Validation ပြ။
3. **Payroll Processing** → Period ဖန်တီး → **Process** → Review တွင် ဝန်ထမ်းတစ်ဦး၏ တွက်ချက်ပုံကြည့်။
4. **Approve** → **Mark as Paid**။
5. **Payslips** တွင် စလစ်တစ်ခုဖွင့်ပြီး ပရင့်ပြ။
6. **History** တွင် Chart ပြ။

## 9. Production သို့ မရောက်မီ လိုအပ်သည်များ (Customer ကို ရိုးသားစွာ ပြောရန်)

| လိုအပ်ချက် | အခြေအနေ |
|---|---|
| မြန်မာဥပဒေအရ **Income Tax** တွက်ချက်မှု | မပါသေး — ထည့်ရန် လိုသည် |
| **SSB (လူမှုဖူလုံရေး)** ထည့်ဝင်ကြေး | မပါသေး — ထည့်ရန် လိုသည် |
| ဘဏ်ငွေလွှဲဖိုင် / ဘဏ်ချိတ်ဆက်မှု | မပါ |
| ဒေတာအမြဲသိမ်းဆည်း (Database) | လက်ရှိ Reload လျှင် ပျောက် — Backend လိုသည် |
| Role အလိုက် လစာကြည့်ခွင့် ကန့်သတ်မှု | UI နမူနာသာ — Server-side လိုသည် |

ဤအချက်များကို Project Scope တွင် သီးခြားထည့်သွင်း သဘောတူညီပါ။
